# 0023 · AI: one way in, one model, every call's cost recorded

- **Status:** decided and built, parts 1 and 2 (21 Oct 2026, project lead).
- **Date:** 21 Oct 2026
- **Scope:** how the backend asks an AI, which provider and model, and how each call and its cost are recorded. It
  covers no use yet: the first, the covering letter's paragraph, is part 2 (below).

## Context

On 21 Oct 2026 Masti sent two of their covering letters (France tourist, France business) and said they write every
letter in ChatGPT, because each one is different. In the two letters most of the text is the same each time: the
consulate, the travellers' table, the dates, the hotels, who pays and the closing. Only the paragraph on why they travel
changes from person to person. The project lead chose to have **the CRM write that paragraph with AI**, from what the
case already holds, with no typing first. Staff can then change the letter's text freely before making it. That goes
beyond the demo ([change request 11](../change-requests.md)) and changes [0019](0019-covering-letters.md) Decision 2,
which is part 2's to record.

More AI uses are coming: filling an enquiry from a WhatsApp message or screenshot (PID ✅, §14), ticket screenshots
(Q20) and holiday itineraries. So the lead asked for **one central place for AI, with one model**: Claude Haiku 5.5,
the cheapest (about ₹0.15 a letter, against about ₹5 on Opus 5.5). Every call is tracked with its cost, with **no
spending limit** (golden rule 11: every paid service gets a line on the running-cost sheet).

This mirrors the WhatsApp sender ([0020](0020-whatsapp-sending.md)): one way out, one file per provider, picked in
`.env`, and tests never call the real service.

## Decisions

1. **One way in:** `askAi({ useCase, system, prompt, userId?, enquiryId? })` from `src/lib/ai` returns
   `{ text, callId }`, or throws an `AiError` in plain words.
   - Nothing outside `src/lib/ai/` names a provider or a model, and no feature makes its own client.
   - **Never call it inside a database transaction:** an answer can take seconds.
   - The prompt carries only what the answer needs, never a passport number. The AI service is outside Masti's servers.
2. **Providers, picked by `AI_PROVIDER`:**
   - `off` (the default): no AI. `askAi` throws "AI isn't set up yet."
   - `fake`: a fixed answer, for a laptop with no key and no bill (as `WHATSAPP_PROVIDER=log`). Its token counts are
     guessed from the length; its model, `fake`, has no price. The server warns at start-up if production uses it.
   - `anthropic`: `anthropic.ts`, with the official `@anthropic-ai/sdk` (pinned at 0.134.0) and `ANTHROPIC_API_KEY`. A
     missing key doesn't stop the server: only AI says "AI isn't set up yet: add ANTHROPIC_API_KEY to Backend/.env.", as
     Twilio's missing keys do.

   Another provider is one more file, one more `case` in `provider.ts` and one more name in `env.ts`.
3. **One model for everything:** `AI_MODEL`, `claude-haiku-5-5` (the project lead, 21 Oct 2026). Changing it is one
   line in `.env`. Its price must be in `prices.ts`, or calls are recorded with no cost.
4. **Every use is in one list,** `src/lib/ai/useCases.ts`:
   - each has a code (`ai.test` now; `visa.coveringLetter.purpose` in part 2), a label in plain words, `maxTokens` and
     an `effort`;
   - `maxTokens` leaves room for the model's thinking, which counts towards it;
   - every call names its use, so the cost can be shown per use.
5. **How we ask Haiku 5.5:**
   - `messages.create` with the model, `max_tokens`, the use's standing instructions as `system`, one user message, and
     `output_config.effort`;
   - thinking stays at its default, adaptive; the effort sets how much of it there is;
   - no `temperature`, `top_p` or `top_k`, and no half-written answer for it to continue (a prefill): Haiku 5.5 refuses
     them all;
   - the answer is read from the text blocks only, since an answer can start with thinking blocks;
   - 30 seconds, and one more try (the SDK repeats a timeout, a busy or overloaded answer and a dropped connection), since
     someone is waiting on the click;
   - with a user key (`sk-ant-usr-…`), which belongs to no workspace, every call names the workspace to bill
     (`ANTHROPIC_WORKSPACE_ID`, sent as the `anthropic-workspace-id` header). Without it Anthropic refuses the call
     ("This API key is not scoped to a workspace"), as it did on 21 Oct 2026. A key made inside a workspace
     (`sk-ant-api…`) needs none.
6. **Every outcome is recorded, and a billed one keeps its tokens.** The provider gives back the text, the tokens and why
   it stopped; `askAi` decides:

   | The AI… | Status | Staff read | Worth another try |
   | --- | --- | --- | --- |
   | answered | `OK` | the answer | |
   | declined (`refusal`; Haiku has no fallback model) | `REFUSED` | "The AI wouldn't write this one. Please write it yourself." | no |
   | stopped short (`max_tokens`) | `FAILED` | "The AI's answer was cut off. Please try again." | yes |
   | answered with nothing | `FAILED` | "The AI gave an empty answer. Please try again." | yes |
   | wasn't reached, or refused the request | `FAILED`, no tokens | wrong key, no access, busy (429 or 529 overloaded), too slow, couldn't reach it, else Anthropic's own sentence | busy, slow, unreachable and 5xx: yes |

   The call is written down first, then the `AiError` is thrown. Every route gets the same HTTP answer for it (part 2,
   `middleware/error.ts`): 503 `{ message, details: { code: "AI_FAILED", retryable } }`, and the screens show the message.
   **For deployment:** the proxy's read timeout must exceed 60 seconds (30 s, tried twice), or a slow answer reaches staff
   as "Can't reach the server" while the call is still billed.
7. **The `AiCall` table:** the use, the provider, the model, the status, tokens in and out, the cost, how long it took,
   the error, who asked and the case.
   - **The prompt and the answer aren't kept:** they hold client details. A feature keeps what it needs (part 2 keeps
     the letter on the case).
   - Not audited (a call changes nothing), and written outside any transaction.
   - One server-log line per call (the use, model, status, tokens, cost and time), never the prompt or the answer.
   - The database refuses:
     - a blank use, provider, model or error;
     - a negative number;
     - tokens in without tokens out (or the other way round), and a cost without tokens;
     - an `OK` or `REFUSED` call without tokens;
     - an `OK` call with an error, or a `FAILED` or `REFUSED` one without one.
8. **Cost in whole micro-dollars** (`costMicroUsd`, $0.000001), as money is whole paise
   ([0009](0009-visa-invoice.md) Decision 2).
   - The AI is billed in dollars, so no exchange rate is stored: reports convert.
   - `prices.ts` holds micro-dollars per million tokens, checked on 21 Oct 2026:

     | Model | In | Out |
     | --- | --- | --- |
     | Haiku 5.5 | 100,000 | 500,000 |
     | Haiku 5.5, a prompt over 100K tokens (every token of that call) | 500,000 | 2,500,000 |
     | Sonnet 5.5 | 2,000,000 | 10,000,000 |
     | Opus 5.5 | 4,000,000 | 20,000,000 |

   - Rounded once, half up: `floor((in × rate in + out × rate out + 500,000) / 1,000,000)`.
   - Tokens read from a cache count as tokens in. The CRM doesn't use prompt caching, so its cheaper rates aren't listed.
   - A model with no price keeps its tokens with no cost. A covering-letter paragraph (about 2,500 tokens in, 1,000 out)
     is about 750 micro-dollars.
9. **A test command:** `npm run ai:test` asks for one short sentence through the chosen provider and model. It prints
   the answer, the model, the tokens, the cost and the time, or the plain-words reason.
   - It writes an `AiCall` row like any call, so the database must be running.
   - On a built server: `node dist/src/scripts/aiTest.js`.
10. **Tests never call the AI:** `vitest.config.mts` forces `AI_PROVIDER=off` and blanks the key, whatever `.env` says.
    `tests/ai.test.ts` keeps the real SDK and its errors but sends its requests to a stand-in, and swaps `aiProvider()`,
    as `messages.test.ts` does for WhatsApp.

| Setting (`Backend/.env`) | Default | Meaning |
| --- | --- | --- |
| `AI_PROVIDER` | `off` | `off`, `fake` or `anthropic` |
| `AI_MODEL` | `claude-haiku-5-5` | The model every AI use runs on |
| `ANTHROPIC_API_KEY` | empty | Needed for `anthropic`. Never committed |
| `ANTHROPIC_WORKSPACE_ID` | empty | Only for a user key: the workspace to bill (`wrkspc_…`). Not a secret |

## Getting a key

1. Sign in at console.anthropic.com. The account and its bill should be Masti's own before go-live (M48).
2. **Settings → Workspaces → Create workspace**, e.g. "Masti CRM".
3. Make a key and paste it after `ANTHROPIC_API_KEY=` in `Backend/.env` on the server. Never in a chat or a commit.
   - A key made inside the workspace (`sk-ant-api…`) is all it needs.
   - A user key (`sk-ant-usr-…`, the only kind the project lead's account gave on 21 Oct 2026) also needs the
     workspace's ID (`wrkspc_…`, under Settings → Workspaces) after `ANTHROPIC_WORKSPACE_ID=`.
4. Set `AI_PROVIDER=anthropic` and run `npm run ai:test`.
5. The workspace's own spend limit and usage page in the Console are a second check on the CRM's own record.
